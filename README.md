# Dead Signal — Unity FPS prototype

Open `Assets/Scenes/Compound.unity` in Unity 6000.5.2f1 and press Play. Choose **Play / Deploy** from the main menu. Missions opens the level selection screen: Outpost 17 (8 guards), Freight Depot (10), and Relay Station (12). Clear each area and reach extraction to unlock the next mission. Use Armory to purchase and equip weapons with earned credits.

See **[UPGRADE-GUIDE.md](UPGRADE-GUIDE.md)** for progression, store, audio replacement, graphics presets, exact Inspector configuration and standalone verification instructions.

Windows build: `Builds/DeadSignal/DeadSignal.exe`. Keep its adjacent data folder and DLLs together when copying the game.

## Controls

| Action | Input |
|---|---|
| Move / look | WASD / mouse |
| Sprint / jump | Left Shift / Space |
| Crouch (hold) | Left Ctrl or C |
| Fire | Left mouse |
| Rifle 3x scope / pistol aim | Hold right mouse |
| Reload | R |
| Selected primary / alternate starter weapon | 1 / 2 |
| Pause / resume | Escape |

Settings include mouse sensitivity, master/music/effects volume, quality, fullscreen and resolution. Preferences persist between sessions.

## Implemented systems

CharacterController movement, acceleration, crouch clearance, camera bob, recoil and weapon sway; automatic rifle and semi-automatic pistol with separate ammunition and timed reloads; 2x headshots; NavMesh guards that patrol, hear shots/footsteps, investigate, chase, attack and search; objective tracking, extraction, death/restart, pause and campaign progression. Hits produce pooled red droplets and temporary irregular floor splatters. Detailed primitive soldiers include faces, helmets, goggles, tactical gear and procedural walking animation.

Art and synthesized audio are original placeholders. Characters are stylized rather than photorealistic. The three levels are variations of the industrial compound with changed cover, structures, lighting, enemy counts and difficulty. The 60 FPS cap is a target, not a measured hardware performance guarantee.

## Editing

Runtime code is organized under `Assets/Scripts` into player, weapon, AI, manager, UI and system components. Weapon tuning lives in `Assets/Prefabs/Weapons/CarbineDefinition.asset` and `PistolDefinition.asset`. UI is generated by Canvas components at runtime. Character, weapon, environment and interface prefabs are under `Assets/Prefabs`.

Each mission has a baked NavMesh. Rebuild its NavMeshSurface after changing walkable geometry, and update ObjectiveManager.requiredEnemies when changing guard counts. New instantiated guards need their player references and patrol points assigned. Standalone weapon prefabs need an aim camera and PlayerLook; the player prefab already contains these internal links.

`AgentScripts` contains external Unity Editor construction and verification tools, not runtime game scripts. Construction scripts are one-time generators; do not rerun them on customized scenes without reviewing their replacement behavior.

## Verification

`VerifyCore.cs` checks ammo depletion/conservation, headshot multiplier, single death notification and navigation to extraction/elevated cover. `VerifyMissions.cs` runs all three missions through shooting, blood activation, timed reload, objective completion, next-level transitions, death/restart and return to menu. Successful results are saved in `Verification/mission-verification.txt`. Rifle scope was checked through simulated right mouse input: active overlay and 28-degree FOV, with an inspected Game view capture.

The older verification scripts intentionally control characters and kill guards to exercise state transitions; run them only in a disposable Play Mode session. They predate progression locking. Use the new isolated standalone `-fps-benchmark` check described in UPGRADE-GUIDE.md for the upgraded game. Test changes after a fresh Play Mode entry rather than recompiling during gameplay.
